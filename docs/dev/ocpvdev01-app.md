# Troshka development app on ocpvdev01

The dedicated app lives in namespace `troshka-dev`, Helm release `troshka-dev`.
URL: https://troshka.apps.ocpvdev01.dal13.infra.demo.redhat.com

The initial application images were built from committed source
`500edb408d7ded5616867d0d4887947106d0a09d` using binary OpenShift builds
`troshka-backend-1` and `troshka-frontend-1`. Both completed successfully.
Their named tag is `v2026.11.13-170117-dev` in the namespace's internal registry.
Production registry tags and the existing shared operator were not changed.

Configuration is in `deploy/helm/values-ocpvdev01.yaml`. This instance has its own
10 GiB PostgreSQL PVC, Redis, two workers, one tunnel replica, and a 50 GiB S4 PVC.
Secrets are generated by Helm and retained on upgrade. Do not copy production
credentials or data into this instance. OpenShift OAuth is enabled; initial admin
bootstrap requires the exact user's OpenShift login identity. No administrator
was seeded during initial installation while that identity was pending.

Upgrade from the repository root:

```bash
helm upgrade troshka-dev deploy/helm \
  --kubeconfig="$HOME/secrets/ocpvdev01.dal13.infra.demo.redhat.com.kubeconfig" \
  -n troshka-dev -f deploy/helm/values-ocpvdev01.yaml --timeout 10m
```

Once the initial administrator is known, add
`--set-string auth.initialAdmin=EXACT_LOGIN_IDENTITY` to that command. This seeds
the first admin without overwriting an initialized access policy. Later access
changes belong in the application's Users administration page.

The chart's upstream S4 default at installation lacked `radosgw-admin`. The dev
installation instead uses the repository-documented compatible source image
`quay.io/rh-aiservices-bu/s4@sha256:25f29f0953e17627bc3f8fb04f6be51a00b10a2599d3c8ab3a2bdb76511ebc90`,
imported under the named tag `v2026.11.13-170117-dev-compatible`. This is a dev
compatibility choice, not a claim that the image fixes multipart-storage issues.

Initial verification: all deployment/statefulset replicas ready, API health HTTP
200, OpenShift login redirect HTTP 302, unauthenticated app access denied, and
backend `HeadBucket` succeeded for the private `troshka-images` bucket. Deployed
`quota_cleanup.py` matched the source SHA-256. Helm revision 2 records the working
S4 image selection.

Native quota enforcement remains disabled. App installation does not certify
KubeVirt/Ceph physical accounting, cleanup, or initialization-profile acceptance.
No workload provider has been registered in the fresh app database yet.

Rollback must preserve both PVCs and generated Secrets. Review the prior Helm
revision before rolling back; revision 1 contains the incompatible S4 image.
Do not delete the namespace as a routine rollback.
